🤔 什麼是搜尋演算法？
想像一下，你要在學校的「置物櫃」找朋友的物品，或是從「電話簿」找某人的號碼。你可以從第一個櫃子開始一個一個打開看（循序搜尋），或者如果你知道號碼牌是按順序排好的，你可以直接從中間翻開，看要往前找還是往後找（二元搜尋）。這就是電腦找資料的方法！
開始體驗 循序搜尋 (Linear Search) 開始體驗 二元搜尋 (Binary Search)

循序搜尋 (Linear Search) 不需排序

這是最簡單直觀的方法。電腦會從第一筆資料開始，一個接著一個往後檢查，直到找到目標，或是全部檢查完發現找不到為止。

💡 老師提示 循序搜尋的好處是「資料不用排好隊」就能直接找。缺點是如果運氣不好，目標在最後一個，就要花很久的時間！
準備就緒。請輸入數字並按下「自動播放」或「下一步」。

二元搜尋 (Binary Search) 必須排序

這是一種非常聰明的方法！前提是資料必須先由小到大排好。它每次都會挑選「中間」的資料來比較，如果目標比較大，就往右邊找；如果比較小，就往左邊找。每次都能淘汰掉一半的資料！

💡 思考問題 為什麼二元搜尋每次都可以排除一半的資料？如果資料沒有照順序排好，二元搜尋還能準確排除嗎？
請注意：下方的資料已經由小到大排序完成！請開始搜尋。
L (Low) 左邊界 | M (Mid) 中間值 | H (High) 右邊界

📊 搜尋演算法大比拚

比較項目 循序搜尋 (Linear Search) 二元搜尋 (Binary Search)
資料前提 不需排序 (任何情況都能用) 必須排序 (未排序會找錯)
搜尋方式 從頭開始，一個一個檢查到底 從中間切開，每次淘汰一半
適合情境 資料量少，或是資料經常變動來不及排序時 資料量大，且資料已經排好順序時
效率概念
(時間複雜度) 		O(n)
資料如果變 2 倍多，最倒楣的情況下，檢查次數也會變成接近 2 倍。 		O(log n)
就算資料變「非常多」，檢查次數也只會「慢慢」增加。效率極高！

🧭 循序搜尋思考地圖

循序搜尋的想法很直接：從第 1 個開始，一個一個檢查。 如果找到目標就立刻停止；如果一路檢查到最後都沒找到，就表示清單裡沒有這個數字。

1

先設定起點

我們從清單的第 1 個位置開始找。

i = 1
2

檢查還有沒有下一個可以找

如果 i 已經超過清單長度，代表整份清單都看完了。

i > 資料清單長度？ 是 → 找不到 否 → 繼續找
3

看看現在這一項是不是答案

拿「資料清單第 i 項」和「目標數字」做比較。

資料清單第 i 項 = 目標數字？ 是 → 找到了 否 → 看下一個
4

如果找到了，就說出答案並停止

一旦找到，就不需要再往後找了。

說出「找到啦！在第 i 個位置」
停止這個腳本
5

如果還沒找到，就換看下一個

把 i 往後移 1 格，表示下一輪要檢查下一個位置。

i 改變 1
6

回到第 2 步，再檢查一次

更新 i 之後，再重新判斷： i 是否已經超過資料清單長度？

7

如果整份清單都找完了還沒找到

代表這個數字不在資料清單裡。

說出「找不到這個數字...」

🧩 核心積木邏輯：

變數 (i) 設為 1 // 從第1個開始找

重複直到 ( (i) > (資料清單 的長度) )
  如果 ( (資料清單 的第 (i) 項) = (目標數字) ) 那麼
    說出 組合 "找到啦！在第" 與 (i) 與 "個位置" 2 秒
    停止 [這個腳本]
  否則
    變數 (i) 改變 1 // 找不到就換看下一個

// 如果整個迴圈跑完都沒碰到「停止腳本」，代表沒找到
說出 "找不到這個數字..." 2 秒

🛠️ 需要準備的元素與變數：

  • 清單 (List)： 建立一個 [資料清單]，⚠️ 裡面數字必須由小到大排好！
  • 變數 (Variables)： 建立 4 個變數。
    • (目標數字)：玩家想尋找的數字。
    • (L)：左邊界，一開始設為 1。
    • (R)：右邊界，一開始設為清單的長度。
    • (M)：中間位置。每次都是 L 和 R 相加除以 2。

🧭 二元搜尋思考地圖

先不要急著拼積木。二元搜尋可以想成一連串「縮小範圍」的決策。 每一輪都只做三件事：看範圍、找中間、決定往哪邊找。

1

先設定搜尋範圍

一開始整個清單都可能是答案，所以：

L = 1
R = 資料清單的長度
2

檢查範圍還有沒有東西

如果 L 跑到 R 的右邊，代表搜尋範圍已經空了。

L > R？ 是 → 找不到 否 → 繼續找
3

找出中間位置 M

每一輪都先看目前範圍的中間。

M = 向下取整 ((L + R) / 2)
4

比較中間值是不是答案

拿「資料清單第 M 項」跟「目標數字」比較。

資料清單第 M 項 = 目標數字？ 是 → 找到了 否 → 繼續判斷方向
5

決定要保留左半邊還是右半邊

中間值太小

如果資料清單第 M 項 < 目標數字，代表答案在右半邊。

L = M + 1

捨棄左半邊

中間值太大

如果資料清單第 M 項 > 目標數字，代表答案在左半邊。

R = M - 1

捨棄右半邊

6

回到第 2 步，再找一次

更新 L 或 R 之後，搜尋範圍變小了。接著再重新判斷： L 是否大於 R？

🧩 核心積木邏輯：

變數 (L) 設為 1
變數 (R) 設為 (資料清單 的長度)

重複直到 ( (L) > (R) ) // 如果 L 跑到 R 右邊，代表範圍空了
  變數 (M) 設為 向下取整 ( ( (L) + (R) ) / 2 )

  如果 ( (資料清單 的第 (M) 項) = (目標數字) ) 那麼
    說出 組合 "找到啦！在第" 與 (M) 與 "個位置" 2 秒
    停止 [這個腳本]

  否則如果 ( (資料清單 的第 (M) 項) < (目標數字) ) 那麼
    // 中間值比目標小，代表目標在右半邊，捨棄左半邊
    變數 (L) 設為 (M) + 1

  否則
    // 中間值比目標大，代表目標在左半邊，捨棄右半邊
    變數 (R) 設為 (M) - 1

說出 "找不到這個數字..." 2 秒
